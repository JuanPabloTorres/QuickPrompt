# NOVA semantic runtime

Status: implementation under real-model evaluation. See `SEMANTIC_INTENT_AUDIT.md`; no acceptance claim until split reports and headed E2E pass.

## Flow and ownership

Every free-text preparation, visible-browser request, legacy interpretation and command-compatibility request consults the same local `ISemanticIntentInterpreter`. The React app no longer performs a `/command` preflight. Explicit UI buttons retain deterministic contracts. Choosing a displayed source candidate binds its actual ID/revision to the one pending literal task when the submitted task is unchanged. A literal title answer can also bind one fresh real record. Qwen then reinterprets that original USER task with the loaded source; provisional goals, missing-source questions and model summaries do not replace it. A new free-form request keeps its own interpretation. Source selection withholds final execution until a current execution instruction or control. The candidate button closes the clarification modal and presents the resolved result through the same canvas handler.

1. `SemanticPlanning.Context` builds bounded task/UI context from real repository snapshots and session artifacts. UI selection, conversation draft and search candidates have distinct roles. Values are scoped to ID **and revision**. Stale snapshots are marked; they never silently become the latest source.
2. A focused Qwen call selects the entity role, not a database ID. Its context names actual repository capabilities and distinguishes loaded entities from the searchable library. Canonical saved sources and conversation artifacts have different descriptors even when their title/ID/revision coincide. Code binds its unique actual ID/revision. Named searches use the existing SQLite retriever plus real model candidate selection. Close competing scores without unique title evidence and duplicate titles require clarification. For an unbound named-source content proposal, similarity alone cannot choose the source: its actual stored title must be present in the literal current/pending user task, or the user chooses a fresh displayed candidate. Otherwise the plan retains its requested transformation and asks which source to use before generation. Session-bound artifact continuations retain their existing path.
3. Separate Qwen contracts select library workflow (read/copy/fill/prepare/run/control/save-review) and the user's instruction request (revision/new instruction/advice/no authored content). A separate Qwen decision identifies an explicitly additional source-based artifact; changing task/domain alone does not create a new library entity. Code composes these facts into the existing semantic outcomes. Content requests and workflows remain independent: no authored instruction task cannot cancel a valid read/fill/control workflow. Neither classification consumes the other model's suggested answer. Workflow receives the actual instruction excerpt as data. The content-goal classifier receives the literal directive, actual nonempty field names, the one authorized pending user request when present and bounded actual working text to resolve ellipsis. IDs, revisions, availability flags, role state and earlier model questions are excluded from this speech-act view: revision metadata previously biased the model toward an edit, but omitting all working text broke indirect contextual requests. The separate reference/workflow stages retain actual contextual roles, and the editor and clause reviewer receive the actual resolved body. Synthetic classification demonstrations explain the separation of instruction changes and application workflow; they are model examples, never code routing predicates or live permissions. The editor receives the full real body. Advice uses a separate read-only explanation contract with the real excerpt. The installed Qwen3 reasoning capability is used for content treatment. Source-role choices use bounded reasoning for current contexts with multiple candidates; other source-role and workflow enum choices use structured non-thinking output, with synthetic user/assistant demonstrations of source roles and content speech acts. Inferred source queries and the other classifier's answer are excluded from the content/workflow context. Internal schemas are shown to the model and validated strictly in C#.
4. Content requirements for an actual edit/new draft are extracted separately. Language, format and literal clauses require user/prior-context evidence. One focused review can remove inferred language/format defaults. For source-dependent drafts, clause review waits until source resolution has supplied the actual saved or working task body. A separate finite-index review then classifies every proposed literal clause as an editor/library direction, a reformulable semantic requirement, a future-task factual/safety invariant, explicitly requested verbatim text, or unsupported data. Only future-task invariants and explicit literal insertions become verbatim requirements. Audience, readability and tone may be expressed in new wording and still reach the editor through the original literal request and transformation. The review cannot introduce clauses and must cover all indices exactly once. Original source prohibitions and variables are checked independently. The domain requires the returned clauses to be a strict subset of the original proposed clauses; it propagates those reviewed requirements to both generation and final validation. Independent new tasks do not borrow an incidental selection's body. New artifacts based on an unsaved working draft receive that actual body and field names as bounded generator data, with no fabricated saved-source ID. A separate review of actual final-task execution may narrow the proposed executor capability, never grant one. Harmless preparation and provider-display goals remain separate typed objectives; they cannot call the final executor. Shortening is a typed semantic flag passed to the existing editor, rather than a word-based routing decision. New/rewrite proposals require a describable content task, and source access cannot coexist with a missing source reference.
5. `SemanticPlanCompiler` adds domain prerequisites to the model-selected goals. `SemanticPlanValidator` checks graph coverage, registered capabilities, source IDs, negative effect ceilings, execution evidence and budgets. Missing source references produce a tagged domain clarification. A typed edit/creation with no described content task also asks before generation, withdrawing every workflow effect; it cannot run a partial plan. Other invalid contracts receive at most one interpretation retry before rejection.
6. The existing preparation tools execute the validated graph. The existing generator, variable resolver, deterministic compiler and validation pipeline produce an ephemeral proposal. Source revision is checked before each operation. Content receives at most one correction; source clauses and variables remain independently checked. NOVA edits pass a typed interpretation alongside the literal user request. Validation feedback and approved preferences are separate fields, never appended into claimed user authority. Qwen3 template editing uses its verified reasoning mode after actual non-thinking probes echoed workflow requests into the template. Desktop/direct-client overloads retain their existing behavior.
7. The lienzo presents the actual returned proposal in React. The visible worker receives the validated semantics and only the finite tools currently applicable to actual UI state. Native Qwen tool decisions operate real React controls. Session drafts are loaded via a trusted internal artifact binding, not model-provided draft text.
8. Saves still use existing explicit approval and optimistic concurrency. Natural save requests mean review, never approval. Preparing for Qwen cannot call the final executor. Explicit local execution requires a ready compiled snapshot and grounded instruction evidence outside quoted data.

Exact field labels and actual template input names identify supplied data independently of the intent classifier. The original request is preserved. Reference/workflow views mask grounded literal value spans. The content-authorship view removes complete grounded field assignments, including labels, from the current and authorized pending directive; only actual field names remain as supplied-input facts. A synthetic replacement marker is not presented as user-authored instruction text. Previous input values are represented as scoped availability metadata, not implied instructions. When a validated fill operation supplies natural descriptions instead of labels, a separate strict Qwen contract may extract values for actual fields. C# requires exact literal evidence and rejects unknown fields, duplicate values and invented content. Repeated contradictory labels remain unresolved. Current explicit UI values and current literal data take priority over session values; existing scoped values precede the older pending request.

The source-role response contains only a role. It distinguishes source-free tasks from unresolved references; the latter cannot become independent creations merely because their source is missing. Only a named-source choice invokes a separate query extractor. Its source descriptor is linked to an index in the literal authorized user passages; code supplies the original text instead of asking the model to reconstruct a quote. Unresolved references stay questions, rather than turning a content change into a lookup. It cannot claim an unloaded record is absent. A source-based content goal can bind the one actual conversational artifact even when the UI selects another record; independent new tasks do not inherit that binding. The source-role model chooses a unique real role once; the former second index selector was removed after it overrode correct choices. A distinct finite source role represents an unidentified member of a found set and requires clarification. Actual current contexts with multiple candidates use bounded Qwen reasoning; unbound named lookup/ambiguity and simple roles use structured non-thinking output. A new-artifact identity decision receives the actual task when an otherwise source-free creation has a current artifact: it may identify an additional copy of that task or retain a genuinely independent creation. Code binds only the known current role/ID; it never invents a source or chooses from an ambiguous set. Completed model plans and generated search queries do not become user permissions. Each proposed local preparation, execution or provider goal undergoes a focused scope review that can only narrow capabilities. Local preparation also requires independently extracted, literal evidence of the requested model destination. Variable-preservation metadata is constrained to actual source field names and independently checked against the generated body.

Visible source clarification retains the same single literal pending request as the canvas. Advice completes without launching Edge. Cancelling a continued pending task clears that pending task while restoring the preceding artifact if no approved write committed.

Selecting or opening one search result retains the bounded alternatives from that search. The same rule applies to source-title replies, editor snapshots and visible completion. Reading/saving a known source refreshes its actual revision in that set. Source-scoped values remain separate from values on an unsaved artifact. Failed generation preserves the previous working artifact while keeping any newer editor snapshot.

## Boundaries and limits

- No new dependencies, model downloads, databases schemas, remote service or general agent framework.
- Temporary context: at most 100 sessions, two-hour expiry; candidate/entity text and draft previews bounded. Oversized authorized context is rejected visibly rather than silently dropping private inputs.
- Semantic plan: at most 12 operations by default (configuration 3–16), one interpretation retry, existing per-stage 90-second and total preparation 180-second deadlines. The headed worker keeps its existing 12-decision/eight-minute bound.
- The model can request only registered operations. SQL, shell commands, arbitrary URLs, executable code and model-provided selectors are unavailable.
- Source changes invalidate effects and saved proposals. Neither diagnostics deletion nor duplicate operation IDs authorize replay.
- A pending clarification retains only its one literal earlier user task plus the current reply. The model must explicitly identify continuation; a model summary never becomes user-provided data. Applicable prior constraints survive reading the same working artifact. Explicit current values and current labeled inputs override scoped session values; old values cannot leak into another source/revision.
- Editor exit first snapshots the actual unsaved body. Explicit saving then snapshots the actual new revision as the conversation context, without an additional saved version. A failed context update keeps the editor open. Reading an active unsaved proposal displays that body rather than silently substituting its original saved source.
- Recovery/undo selects an actual stored draft using `/nova/sessions/{id}/draft-context`; completing its fields preserves its semantic context and never starts inference automatically.
- Main-canvas mode supports independent new drafts and new drafts inspired by a source. Headed-browser mode retains its existing scope of operations on saved prompts; a new-draft request is explicitly blocked with a direction to use the lienzo.
- Raw Qwen outputs are captured only by test-owned observers/proxies against synthetic fixtures. Production activity records contain redacted metadata; session content is not copied into general logs.

## Reproduction

Use installed .NET 8, Node dependencies, Edge and Ollama Qwen3:8b. Scripts do not install, restore, download or publish.

`scripts/Test-SemanticIntent.ps1` builds and runs source tests. Its real-model option evaluates development, then validation, then untouched holdout, stopping at the first failed gate. With `-Headed`, it also runs real headed UI acceptance against a fresh synthetic SQLite file. Artifacts include actual model requests/replies, plan/tool traces, screenshots, browser recordings and source-version checks.

Do not run multiple real-model suites at once: they share one local Ollama instance. Test output directories are unique; unsuccessful experiments remain available and are never relabelled as acceptance passes.

## Reparación de contratos y contenido

La interpretación mantiene un único reintento global para contratos inválidos o contradicciones tipadas de origen/workflow. Además, el contrato independiente de contenido dispone de una sola reparación local por petición para reconciliar su tipo con la cita literal de evidencia. Esta reparación no repite búsqueda ni herramientas, no recibe errores de la etapa de referencias y no puede conceder ejecución. Ambas permanecen dentro del mismo límite de 90 segundos de interpretación. Si la cita sigue ausente/no literal o el tipo sigue siendo contradictorio, el plan retira los efectos y solicita aclaración. No hay bucles abiertos de reparación.

Los campos de entrada aportados se representan mediante sus nombres, sin promover sus valores a instrucciones de autoría. Los identificadores técnicos esenciales extraídos de la petición son requisitos independientes de acortar el texto; los destinados solo a ejecutar el prompt no son requisitos de su contenido. Una revisión de alcance con el origen real puede retirar un término editorial o un título, pero no inventar requisitos ni conceder efectos. El editor recibe los términos mediante un enlace interno JsonIgnore desde el plan validado. El único reintento de generación recibe el candidato rechazado, cláusulas/identificadores omitidos, variables exigidas y longitud permitida.

En el paquete privado enviado al modelo, `validationFeedback` es un objeto JSON y `previousDraft` contiene el candidato efectivamente rechazado cuando está disponible. No se codifica una segunda vez el objeto dentro de una cadena ni se mezcla con `authorizedUserRequest`. Un contrato de corrección mal formado se rechaza; no modifica APIs públicas ni esquemas SQLite.

El candidato aparece una sola vez: se retira su copia de feedback y la instrucción genérica repetida, conservando los fallos y requisitos efectivos. En las ediciones semánticas, el esquema se transmite mediante `format`, sin duplicarlo en el mensaje del sistema. La cota conservadora de contexto, la reserva de salida y el rechazo de entradas demasiado grandes se mantienen.

En ediciones semánticas, las cláusulas protegidas que faltan se retienen literalmente desde el origen canónico antes de validar el resultado. No se agregan transformaciones, destinos ni hechos inferidos. La conservación se anuncia mediante SOURCE_INVARIANTS_RETAINED como regla determinista, no como decisión de Qwen. Restaurar por sí solo una cláusula suprimida no constituye un cambio real; siguen siendo obligatorios el cambio solicitado, las variables y los límites de longitud. Las propuestas con JSON mal formado se rechazan con un error de validación. Las llamadas legadas sin interpretación tipada mantienen la corrección y el rechazo anteriores. La detección conservadora de cláusulas del origen cubre determinadas formas imperativas en español/inglés, no cualquier restricción en cualquier idioma.

El dominio compone también los campos canónicos omitidos en `Entradas / Inputs`, usando únicamente nombres procedentes de `TemplateCompiler.Names(source)`. No inventa datos ni acepta nombres nuevos. El compilador existente aplica después los valores reales a esos campos. Los campos presentes en el cuerpo o en una cláusula conservada no se duplican. La composición es idempotente y no puede superar el límite final de longitud ni convertirse por sí sola en una supuesta adaptación. `SOURCE_INPUTS_BOUND` identifica la regla en el agente visible; la propuesta del lienzo incluye una nota propia del sistema. El texto final compuesto se somete a los mismos controles que el texto generado.

Una operación SEARCH no sustituye una referencia contextual cuyo ID/revisión ya está vinculado. Un artefacto sin guardar tampoco adquiere por ello una identidad de biblioteca. La comprobación de revisión se mantiene antes de utilizar el origen.
