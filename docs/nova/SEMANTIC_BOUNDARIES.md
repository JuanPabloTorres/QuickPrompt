# Request interpretation boundaries

Status: implementation under evaluation; the new TaskGoal interpreter remains disabled by default. This audit does not establish semantic accuracy or latency acceptance.

The user requested removal of keyword, regex and pattern-based request recognition. Intent, reference role, negation scope, template changes, input relevance and destination meaning belong to Qwen. Application code owns the allowed operations, actual identities/revisions, provenance, authorization ceilings and observed postconditions.

## Changes

| Boundary | Previous dependency | Current behavior |
|---|---|---|
| Legacy assist input | Fixed Spanish/English command words and prefixes; unmatched input could open the first search match | All free-text submissions use the existing local model planner. The returned typed plan is validated and presented for review. No first-match fallback. |
| Direct template editing | Regex inferred shortening from selected phrases | A supplied semantic requirement is authoritative. Otherwise the same generation response must contain a typed `shorteningRequested` decision. A correction cannot withdraw that requirement. There is no additional classifier call or keyword fallback. |
| TaskGoal evidence | C# split sentences on punctuation and Spanish/English conjunctions, then forced one role per fragment | Qwen selects global ranges of original words for each typed effect. Code extracts exact authority and derives domain roles from operations. Coupled effects may share evidence; a separate interpreted template instruction is generation data, never application authority. Decoder endpoints exclude masked field data; code also rejects ranges crossing those data/origin boundaries. With no available directive words, only a question with null evidence is admitted. |
| TaskGoal conversation | Synthetic user demonstrations could be copied as live authority | After observing actual copied clauses, demonstrations were removed. Initial inference has only the system contract and actual context/directive. Bounded repair sends domain feedback separately without replaying the rejected answer as authority. |
| Reference identity | Independent role/ID/query fields could contradict each other | Context-specific source objects own their allowed fields. Current/previous/other roles bind actual context IDs in code, known candidates use only supplied IDs, library lookup owns its description, and no-source has no ID/query. |
| Generation data | Authorship evidence also had to be a disjoint fragment suitable for the editor | Interpreted template-edit instruction/requirements have their own owner; application operations are separate metadata. This cannot introduce an effect or approval. Search criteria never become template-edit requirements. Real generative fidelity remains an evaluation gate. |
| Authorship ownership | An independent nullable edit could accompany read/search operations; the model sometimes returned an edit containing the string `null` | A private discriminated contract selects `NO_AUTHORING`, `PROPOSE_ADAPTATION` or `CREATE_DRAFT`. Only the latter two own evidence and an edit. Workflow effects cannot contain authorship, and no-authoring objects cannot contain edit data. Code compiles these into the existing public plan. This prevents contradictory payload shapes; it does not prove that the model selected the correct role. |
| Clarification control | Any nonempty question could suspend an otherwise complete authoring plan | Only the explicit typed `ASK_CLARIFICATION` action suspends a goal. An authoring question without that action is rejected within the existing bounded repair budget. Actual source ambiguity remains the resolver's responsibility; persistence retains separate human approval. There is no phrase-based detection or automatic dismissal of genuine questions. |
| Action evidence | Decoder accepted `quote: null` for every workflow operation even though code later rejected it | Separate schema branches require actual word ranges for every action except `ASK_CLARIFICATION`. Scope repair retains those branches and narrows their operation enums without adding capabilities. Literal data stays excluded from available authority ranges. |
| Content format | Availability depended on literal format-name matches in a fragment | Qwen selects supported normalized formats semantically. The finite enum describes service capabilities; it is not a list of natural-language trigger words. Literal content terms still require actual source wording. |
| Destination permission | Provider aliases and local-model phrases had to occur literally | A typed semantic review distinguishes an AI destination, a source identity and an unspecified destination. Code requires an actual allowed provider, exact target evidence and an authorized supporting passage; preparation is separate from execution and sending. |
| Input-use scope | A rewrite could fill inputs only when particular field-name words were found | Semantic input-use selection is checked against an actual input contract. Code validates actual names, literal values/evidence and native observations. |
| Field values | Special summary/length vocabulary and a fixed material-field alias list | Field relevance is inference's responsibility. The resolver applies the same literal provenance rules to every real field. Explicit values, defaults, session values and actual template labels remain distinguishable. |
| Retrieval | Fixed bilingual synonym groups and command-word exclusions | SQLite performs bounded literal recall from the supplied query. Qwen owns source interpretation/query generation and candidate selection. Retrieval scores grant no action or identity authority. |
| Lookup dependency | A typed lookup description with target NONE could ask for a title before searching | An explicitly selected search with a nonempty query and no ID enters the existing lookup route. A stray query cannot grant search to unresolved open/edit or independent creation. This does not classify user wording or invent an identity. |
| Named-source questions | A model question accompanying a named read was rejected before the actual lookup | Pure named read/search goals proceed to the resolver, which inspects real records and asks when identity remains ambiguous. Questions do not choose a source or grant extra effects. Other workflow-question and execution guards remain. |
| Authored-content fidelity | Changed/shorter native text could still omit the requested purpose | Experimental goal-mode creation/adaptation receives an independent content assessment before returning the proposal. The assessment compares actual authority, source and candidate; it can reject and consume the existing bounded correction budget. Native receipts, source identity, compilation and human approval remain code checked. Assessment origins are typed references to actual data, never reconstructed user authority or new permissions. Reviewer reliability requires its own real-model evaluation. |
| Visible adaptation | The same-window proposal endpoint bypassed the preparation generator's new assessment | The server attaches its validated goal internally and both entry points use the same generator. HTTP JSON cannot inject that authority. Source identity and bounded correction remain checked. |
| Semantic postconditions | Legacy validation required language/format words to occur literally in the instruction | Only an exact, goal-bound assessed artifact uses the semantic assessment for these requirements. Unassessed and legacy content retains its previous checks. A receipt cannot replace literal invariants, field/preview verification or human approval. Changing authority/body invalidates the assessment. |
| Correction capacity | The shared editor requested a configured 12,288-token context but its local conservative byte/output check always used 8,192 | The check uses the already configured capacity and retains output/framing reservation. Default 8,192 remains unchanged. Tests preserve full UTF-8 source, prior draft and feedback, reject overflow before HTTP, and verify the actual request's context. No model/global context setting was increased and no content was truncated. |
| Approved destination metadata | An adapted-source editor submitted its source revision when applying an approved new copy; the server correctly rejected the different hash and the driver later reported a timeout | Commit reads the current approved proposal's destination revision and sends the actual form content with that metadata. It never replaces current content with the old proposal. The server still checks the approved hash, fresh revision, cancellation and single use. Driver opens activity idempotently and reports a rendered commit error immediately. Recorded synthetic browser/API/SQLite approval and rejection probes pass; they are not model-accuracy or latency evidence. |

## Deterministic parsing that remains

- Placeholder grammar, real field labels/assignments, quoted-data boundaries and JSON/schema validation parse explicit data. They do not decide whether the user requested creation, editing, deletion, execution or saving.
- SQLite tokenization/ranking is literal retrieval. Removing the synonym dictionary does not turn SQL into a semantic or cross-language search engine; semantic query generation and real multilingual retrieval require end-to-end evaluation.
- Source-constraint extraction conservatively protects recognizable clauses in the stored template, including their punctuation. It does not classify the user's action and does not prove that every semantic source invariant has been found.
- Output checks compare required literal terms, compiler output, length, IDs, revisions and receipts. Those checks do not prove general semantic fidelity. Legacy/unassessed output keeps its language/format heuristics; experimental goal content can use its bound semantic assessment instead. The legacy read-only source analyzer is not a request router.

No source of model text can grant approval. Existing save/cancel/revision/idempotency controls remain required. Model interpretation errors must remain visible in real evaluation, rather than being hidden by growing trigger-word lists.

## Validation

R52 backend: 375 regressions and 150 legacy web tests passed. R53 React: 86 tests passed, including approved-control opening and immediate rejection reporting. API/evaluation builds succeeded without warnings/errors; React build passed with its existing bundle-size warning. Transport regressions include original-word ranges, typed authoring/workflow ownership, explicit clarification control, null-evidence rejection, semantic format selection, input masking, foreign IDs, bounded repair, cache eviction and destination roles. Scope-conflict repair cannot add capabilities or mutate structurally validated authoring data; structural validity is not semantic truth. SQLite integration resolves named-source ambiguity without selecting/writing. Context tests preserve complete UTF-8 feedback/source/previous drafts and reject overflow. Content-review tests reject missed purpose, lost constraints, workflow contamination and unknown evidence origins, and bind assessments to the actual body/authority. Controlled replies do not establish real-Qwen comprehension.

R48's real-Qwen reviewer component passed 12/12 development pairs; it was not rerun for the later contract/accounting changes. R52's mandatory native task passed with assessment, body-bound completion and one headed Edge Page in `docs/evidence/latency-1792319238080`: actual fields/preview/copied text matched and the original remained unchanged (95,879 ms, three calls). This run did not need correction, so its success is not causal proof of the capacity fix. Manual inspection still found repetitive/truncated wording. R51's native probes passed variables, explicit pause/resume without pausing on touch, and cancellation. Creation populated native fields but an unrequested copy-readiness goal caused unnecessary missing-variable questions. Complete R51 interpretation development failed its frozen gates (13/16 intent, 15/16 valid plans, 14/16 target, 0/2 paraphrase groups). Validation/holdout remain untouched; no comparable speedup or global acceptance is claimed. TaskGoal stays disabled by default.
