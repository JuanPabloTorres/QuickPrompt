# NOVA en la pestaña que estás mirando

## Uso

Inicia QuickPrompt con `powershell -File scripts/Start-Nova.ps1`. El arranque compila React y la API con las herramientas instaladas; no instala paquetes ni modelos. Para actualizar una instancia antigua conservando tu pestaña, detén su servidor, ejecuta `powershell -File scripts/Start-Nova.ps1 -NoBrowser` y recarga esa misma pestaña.

En «¿Qué quieres hacer hoy?» escribe tu petición y pulsa **Preparar prompt**. La preparación visible es la opción predeterminada. **Opciones de preparación** permite elegir **Solo mostrar el resultado** si lo prefieres. NOVA abre los controles del mismo lienzo, señala el objetivo y escribe por fragmentos. La búsqueda de biblioteca sigue siendo un campo independiente. Las opciones avanzadas permanecen plegadas.

Durante una tarea aparece un botón **NOVA** en la esquina inferior derecha. Pulsa **Actividad de NOVA** para consultar el paso actual, las acciones recientes y elegir velocidad visible o rápida, pausar, continuar o detener. La actividad se cierra sin bloquear el formulario y conserva el acceso por teclado dentro de los diálogos. En móvil el botón se reduce a un icono. Al terminar o cancelar, desaparece; si faltan datos, se muestra la pregunta funcional junto al contenido. **Pausar** detiene el avance; **Continuar** reanuda la misma ejecución. Tocar la pantalla, enfocar un campo, seleccionar texto, desplazarse u ocultar la pestaña no solicita una pausa. Una desconexión breve retiene la acción pendiente y se recupera automáticamente, sin repetir sus efectos. Si se modifica realmente el contenido o se cambia el objetivo durante una acción, la verificación impide sobrescribir el cambio y conserva el borrador para revisión. El borrador que solo estaba en memoria del documento puede perderse al recargar. Recargar pierde la capacidad del documento: detén y solicita de nuevo después de revisar el borrador; no se repiten operaciones de resultado desconocido.

Si el origen no es inequívoco, Qwen pregunta. Responde con el título real o selecciona un candidato; la petición original sigue siendo la autoridad para el cambio. Un borrador nuevo o una adaptación no se guarda por generarlo. **Revisar y guardar versión** muestra el texto y solicita confirmación; el botón real de aplicación consume una aprobación ligada al contenido, origen y revisión. Cancelar conserva el original persistido y deja visible el borrador sin guardar.

## Contrato y límites

`AgentUiDriver` traduce un catálogo finito de herramientas lógicas a controles DOM de React. Usa clics DOM y el setter nativo más el evento input del mismo onChange controlado. Son eventos automatizados, no interacción física confiable del navegador. `NovaAgentCursor` sigue getBoundingClientRect, tiene pointer-events none y respeta movimiento reducido.

El dispatcher de aplicación implementa el puerto de ejecución existente sin iniciar procesos. Un secreto aleatorio por documento viaja en X-Nova-Surface; solo su hash permanece temporalmente en backend. No entra al modelo ni a los eventos persistidos. El canal usa polling de 400 ms y SSE para actividad. Las trazas técnicas, IDs, nombres internos de herramientas y verificaciones permanecen fuera de la interfaz de uso; se conservan en las evidencias de QA. Los ajustes muestran preferencias funcionales, sin diagnóstico de desarrollo. Cada acción tiene RunId, ActionId, secuencia, herramienta, objetivo, argumentos, fecha y estados. Localización/ejecución son progreso; el orquestador espera el recibo verificado y comprueba también identidad, revisión, compilación y persistencia mediante los servicios existentes.

Hay una ejecución incompatible activa y una acción pendiente. Los recibos idénticos se reenvían desde memoria sin repetir los efectos DOM. Recibos incompatibles, fuera de secuencia, de otra superficie o posteriores a cancelación se rechazan. La ausencia de polling no crea una pausa de usuario: el dispatcher espera el recibo de la misma acción. Una acción pendiente tiene un límite de tres minutos y el run conserva su límite global de ocho minutos. La espera de controles DOM excluye el tiempo de pausa explícita. Una corrección de generación no elimina las reglas del dominio.

Cuando todos los efectos pedidos ya fueron observados, la siguiente elección del modelo conserva terminar o solicitar la revisión autorizada y elimina las lecturas opcionales redundantes. La observación real al inicio de cada paso y la validación independiente de identidad, contenido y compilación siguen ejecutándose. No se clasifica la petición mediante palabras clave ni se sustituye la generación de Qwen por texto fijo.

La generación de contenido comparte el generador, el evaluador y el compilador existentes. El modelo decide cuándo crear; el backend valida el contenido antes de enviarlo al formulario real. SQLite solo recibe la creación/actualización final desde el control aprobado del editor. No hay selectores, JavaScript, URLs ni comandos de sistema generados por el modelo.

El clasificador de destino recibe la directiva del usuario, identidades de fuentes y el registro real de destinos; los permisos se revisan sobre la directiva separada de valores de campos. El clasificador de entradas sí recibe la plantilla como datos para relacionar el caso con sus variables; ese cuerpo no concede permisos de destino, ejecución o guardado. El contrato privado separa la acción de destino (preparar, ejecutar ahora o elegir), el proveedor y la intención de rellenar. El registro real traduce esos hechos tipados a las capacidades del dominio. Una comprobación adicional vincula la identidad del destino con sus nombres reales fuera de títulos de fuentes; conocer ese nombre nunca concede permiso para ejecutar. Los objetivos de workflow son independientes de sus requisitos aún pendientes: Qwen interpreta si hay que abrir, rellenar, preparar o ejecutar; cuando una fuente nombrada se recupera después de esa interpretación, se revisan las funciones de contenido y entradas con su cuerpo y revisión reales antes de autorizar efectos. La búsqueda solicitada se conserva en el recorrido visible. Cada fase semántica tiene un límite de etapa de 90 segundos por defecto, dentro de los ocho minutos del run. Los valores extraídos necesitan una cita literal de la petición y un nombre de campo existente. Cuando se solicita preparar o ejecutar con asignaciones explícitas válidas, resolverlas es un requisito del compilador; se registra como regla del dominio, sin atribuirlo al modelo. La prohibición de rellenar sigue bloqueando ese requisito. Los verificadores clasifican cada alcance como solicitado, prohibido o no solicitado y eligen evidencia entre pasajes reales acotados por código; no generan citas libres ni pueden tomar datos de campos como permiso de ejecución. Un borrador nuevo se identifica como tal con promptId nulo hasta que el usuario autoriza su creación; no se inventa un ID persistido. Guardar consume una sola aprobación. Si guardar cambia de vista, el adaptador vuelve a presentar el destino que ya se había solicitado antes de dar la preparación por terminada.

El selector de proveedor prepara una revisión; no envía automáticamente a sitios externos. La extensión MV3 conserva sus permisos. El navegador separado BROWSER está rechazado por defecto; `Start-Nova.ps1 -QaBrowser` lo habilita expresamente para pruebas históricas. Playwright es observador de QA, no dependencia de la ejecución normal.

## Reproducir la validación

La [aceptación actual](SAME_WINDOW_ACCEPTANCE.md) documenta 12 recorridos reales con Qwen, incluidos actividad flotante, móvil, revisión modal, cancelación e intervención manual. Reúne grupos aprobados de tres sesiones de Edge visible con hashes idénticos de API y React, conserva los informes fallidos y declara la comprobación de ocultación que no fue aplicable al minimizar Edge. No afirma una única pasada continua. Las instancias locales se actualizaron con esos mismos ensamblados validados.

Con Qwen3:8b ya instalado y Ollama en 11434:

```powershell
powershell -File scripts/Test-SameWindow.ps1
```

La prueba copia los binarios y React a una salida inmutable, crea una biblioteca sintética y usa API 5236 y proxy local de evidencia 5237. Una única Page de Edge QA observa la aplicación. `PLAYWRIGHT_MODULE` admite una instalación existente distinta. Se guardan interpretación, decisiones, recibos, valores DOM, ventanas/pestañas, capturas y vídeo en `docs/evidence/same-window/`. No instala ni publica y no usa la biblioteca personal.

El modo de prueba predeterminado muestra Edge. `-HeadlessQa` ejecuta las regresiones grabadas sin competir con el navegador personal; esta opción pertenece exclusivamente al runner QA y se registra expresamente en la evidencia. El modo normal de NOVA sigue ejecutándose en la pestaña emisora del usuario. La cuenta de procesos/ventanas se limita al árbol del proceso QA y su API para excluir ventanas ajenas; también se comprueba que no aparezca otro proceso de navegador oculto. Los eventos isTrusted de las pruebas no se presentan como evidencia de movimiento físico del mouse.

La reproducción original de la segunda ventana está descrita en [SAME_WINDOW_AUDIT.md](SAME_WINDOW_AUDIT.md). Las pruebas antiguas de GOAL08 describen la superficie separada histórica; no son aceptación del modo normal actual.
