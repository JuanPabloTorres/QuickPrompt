## Root cause and entry-point audit

| Boundary | Previous semantic inference from text | Replacement |
| --- | --- | --- |
| `LocalCommands.Resolve` | Prefix/verb regex, title stripping, special exclusions, change delimiters, filter-name phrases | Async compatibility endpoint consulting the shared semantic interpreter. It cannot consume adaptations/combined requests. React no longer uses this preflight. |
| `AgentRouting.Deterministic` | Search/open literal fast path and special current-reference operations | Removed. Every natural preparation enters the semantic interpreter. |
| `AgentRouting.MainOperation` | Only promoted adaptation when a short editing-verb regex matched | Removed. Typed user objectives determine the operations. |
| `AgentRouting.RefersToCurrent` | A finite list of pronoun phrases | Removed. Authorized UI and task context are supplied independently of phrasing. |
| `AgentRouting.ExecuteRequested`, `Provider`, `Cancel`, `Unsafe` | Keyword/regex grants, provider identification and special sentence routing | Removed. Model objectives are bounded by typed capabilities, literal execution evidence, registered tools and domain checks. No SQL/shell/external-send capability exists. |
| `UiToolCatalog.UpdateRequested`, `LocalRequested` | Editing/shortening/execution word detection | Removed. Visible-mode permissions derive from the same validated semantic interpretation. |
| React `PreparationCanvas` | Regex deciding whether context may be sent; `/command` before preparation | Removed. Session/UI context is typed data, and a single preparation path presents the result. |
| React `startVisible` | Salutation stripping, verb and pronoun matching | Removed. UI selection is sent as context, separate from the final resolved target. |
| React `liveCommand` | Cancel/pause/resume/save phrase regex | Replaced by semantic interpretation while an actual run is active. Buttons retain their typed direct control contracts. |
| Legacy `NovaInference.Interpret` | Literal help/compile/use commands and `QuickAssistCommands.Parse` | Removed from the web interpreter. The legacy contract projects the shared semantic result. |
| Prior-data clarification in the orchestrator | Special phrases about information previously described | Removed. Missing information and authorized values belong to the semantic/context contracts. |

Remaining literal/token operations are not intent routers: parameterized search recall/ranking; template parsing; exact value/evidence grounding; conservative preservation of source clauses; explicit language/format integrity checks; generic detection of an edit request echoed into generated content; and fixed UI selectors. The desktop legacy command parser is outside the NOVA web entry points and has not been rebuilt.

The unused `CandidateSelection` first-match helper and the heuristic `RequirementExtraction` have also been removed from the preparation pipeline. Visible verification requires the validated semantic requirements explicitly; it cannot fall back to extracting requirements from verbs/phrases. The shared editor's nullable legacy shortening overload remains for desktop/direct-client compatibility; every NOVA web call passes a typed semantic shortening flag.

## Architectural change

`ISemanticIntentInterpreter` produces a bounded, structured interpretation from actual Qwen calls. It distinguishes independent access, draft, execution, control and persistence-review objectives. It supports combined objectives instead of one exclusive intent label.

`SemanticPlanCompiler` expands those typed objectives into dependencies: source resolution precedes an adaptation; structural validation precedes compilation; local preparation precedes actual execution. It does not inspect message words. These dependencies are code-owned domain policy, not claimed model choices.

`SemanticPlanValidator` rejects unregistered operations, inconsistent contracts, forbidden effects, missing dependencies, out-of-context IDs, ambiguous candidate-ID choices, invalid execution evidence and unreviewed persistence. The execution engine only dispatches registered tools authorized by the validated plan. Persistent saves still require the existing explicit UI/API approval and current source revision.

Context is temporary and bounded by the existing 100-session/two-hour policy. Selected UI source, previous candidates, active draft/source revision, last proposal, pending action, applicable constraints and approval state are distinct. No unlimited transcript is concatenated. Changing the UI selection must not erase the active conversational draft or leak its values into an unrelated source.
