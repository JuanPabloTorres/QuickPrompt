## Implemented boundaries

- A process-owned `TaskGoal` retains source identity/revision, requested and forbidden effects, content constraints, required information, completion conditions and explicit persistence requirements. It is not a new public request field or persistent schema.
- `GoalCompletionValidator` checks actual React observations and current execution receipts. Opening a source, an old response or a textual explanation cannot substitute for a required transformation, compiled preview, filled field or approved write.
- Source resolution reads a fresh SQLite revision. New goal mode preserves the authorized interpretation instead of restarting the complete interpreter after each source read.
- Typed UI transitions handle navigation, native fields and verified completion. They are labelled as deterministic execution of a semantic plan, not new model decisions.
- The editor receives scoped content instructions rather than the entire application workflow. Explicit save-copy proposals create a different identity, preserve the source and recheck the source revision at commit. Cancellation, approval hashes and idempotent receipts remain required.
- A real copy action is available for a current compiled draft. Browser QA captures the clipboard handoff inside an isolated browser context; OS clipboard integration is **NOT_TESTED**.
- The new semantic pipeline separates requested content from application workflow. Qwen selects evidence from actual user text; code extracts and validates that evidence. Source bodies and literal field values are not interpreter authority. Quoted data cannot independently grant workflow permission.
