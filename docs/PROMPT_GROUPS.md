# Grupos de QuickPrompt — GOAL 04

**Ubicación actual GOAL05:** biblioteca → Opciones del prompt → Grupos permite crear y asignar en una transacción. Filtros → Grupo filtra; Gestionar grupos abre el gestor contextual y Cerrar organización vuelve a biblioteca. Selección múltiple está dentro de Filtros. Los metadatos del grupo son expandibles. [Regresión actual](evidence/goal05/accepted/goal04-organization/organization.json); los datos y reglas descritos abajo se conservan.

Los grupos son colecciones independientes de PromptCategory. Una plantilla o un Instruction Profile puede pertenecer a varios grupos sin duplicarse. Grupos permite nombre, descripción, icono SVG local, color de una paleta fija, fijación y orden numérico (menor primero). Biblioteca permite filtro de grupo, sin grupo, categoría, favoritos y texto; la selección múltiple agrega o quita relaciones en una transacción. Eliminar grupo borra únicamente sus relaciones. Los contadores de plantillas consideran las activas; archivar conserva su pertenencia para restaurarla.

Persistencia: migración **SQLite 1 → 2** en SchemaMigrations, dentro de la transacción de inicialización. PromptGroups tiene ID y NameKey únicos (comparación sin tildes/case); GroupMemberships tiene PK(GroupId,Kind,EntityId), FK al grupo y FK compuesta a Documents(Kind,Id), ambas con cascada de relaciones. Kind solo admite template/instruction. Índices por entidad y campos de catálogo. La migración no reescribe Payload de documentos previos. Una DB de versión futura se rechaza antes de DDL o backup.

Antes de migrar una DB v1 se genera una copia SQLite consistente junto al archivo: `.before-goal04-<uuid>.sqlite`, sin sobrescribir copias anteriores. Arranques v2 no crean otra copia. Para rollback operativo: detener el servidor, conservar/exportar antes el estado v2, restaurar una copia v1 a una ruta propia y usar el código previo. El código anterior rechaza schema 2; no se debe ejecutar contra él ni borrar tablas manualmente. El rollback a la copia anterior no incluye datos creados después de esa copia. Se prueba rollback transaccional de DDL y de restore mediante fallos SQLite reales.

Respaldo **JSON v2** incluye grupos y relaciones, perfiles, versiones y combinaciones. Se siguen aceptando JSON v1 y formatos legados; restore v1 reemplaza el conjunto completo y por tanto no conserva organización que no exista en ese respaldo. Importar es aditivo: no sobrescribe registros, mapea grupos equivalentes y plantillas/perfiles equivalentes a sus IDs locales y añade relaciones sin duplicación. Un vínculo huérfano o JSON v2 incompleto rechaza toda la operación. Restaurar usa una única transacción para Documents, grupos y relaciones.

La UI usa QueryTemplates con COUNT + SELECT LIMIT/OFFSET y filtros parametrizados. Solo materializa la página solicitada (12 por defecto) y hasta 10 resultados del buscador rápido. La búsqueda mantiene la equivalencia de tildes/case anterior. Hay una regresión con 1000 plantillas y filtros combinados; export/import son operaciones explícitas de snapshot y sí recorren el conjunto. No hay jerarquías, ORM ni dependencias nuevas.

La prueba histórica de «DB futura» ahora inserta CurrentSchemaVersion + 1, en vez del literal 2 que esta fase pasa a soportar explícitamente. Mantiene la misma condición de rechazo y comparación de bytes; no se relaja para hacer pasar una DB desconocida.

El límite JSON se aplica simétricamente al exportar e importar: **32 MiB UTF-8**. Exportar más devuelve un error controlado antes de descargar un archivo que la misma aplicación no podría restaurar. El lector SQLite legado seleccionado conserva su límite anterior de 4 MB. La regresión UI restaura/exporta 450 plantillas, versiones y fechas en 5 003 505 bytes, con fuente intacta, 12 tarjetas por página y búsqueda exacta: [evidencia](evidence/goal04/stage06/large-backup/large-backup.json). Importación de una copia privada real permanece bloqueada por decisión del usuario.

El editor conserva cambios sin guardar al reseleccionar el mismo grupo. Cambiar de entidad recrea controles y los callbacks validan el ID capturado, evitando que un evento antiguo altere el nuevo borrador.
