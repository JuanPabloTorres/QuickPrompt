No se presenta como tokenización exacta ni se recorta contenido silenciosamente. Un texto que exceda el presupuesto devuelve un error controlado y sigue disponible para copiar. ## Calidad del contenido: evaluación separada

Regresión compuesta previa al reinicio Ollama: **2415 ms, n=1**, [evidencia](evidence/goal04/verified/local-ai/local-ai.json). No se agrupan corridas como benchmark ni se cambia el prompt buscando una respuesta más favorable. También se verificó que una respuesta completa todavía sin guardar sobreviva a navegar a Configuración y volver dentro del circuito; solo Guardar resultado la persiste. Reiniciar recupera únicamente resultados guardados. La regresión general [browser-ai](evidence/goal04/verified/regression/browser-ai.json) vuelve a ejecutar mejorar/crear/sugerir/analizar/ejecutar con Qwen3, revisión, aceptación, variables, cancelación y versiones; su muestra de ejecución de 20227 ms usa otro prompt y no es comparable directamente al caso compuesto.

La revisión textual del agente del resultado compuesto previo al reinicio confirma español, tres viñetas, menos de 80 palabras y una ventaja/prueba sugerida, sin afirmar que se ejecutaron pruebas. **Exactitud contextual: FAIL limitado**: el modelo sugirió comprobar el archivo en el directorio del proyecto, mientras QuickPrompt usa LOCALAPPDATA por defecto. La respuesta no se aplica a configuración/datos y requiere revisión del usuario. No se repitió el caso cambiando instrucciones para producir otro resultado ni se modificaron los datasets v1/v2. Esta revisión no es una evaluación humana independiente ni demuestra exactitud factual general; siguen vigentes las limitaciones históricas de Qwen2.5.

La regresión adicional tras reiniciar/confinar Ollama usa **exactamente el mismo caso**, sin corrección del prompt ni dataset: [9549 ms, n=1](evidence/goal04/verified/loopback-local-ai/local-ai.json), incluidos arranque del modelo y streaming. Funcionalidad completa PASS otra vez. La nueva respuesta no afirma la ruta incorrecta, pero su tercera viñeta «Prueba: Funciona bien en apps móviles y desktop sin conexión» es una afirmación genérica, no una prueba concreta sugerida: **calidad semántica FAIL limitado**. No se declara fallo factual para esa frase general ni se borra el fallo contextual anterior. Dos muestras de condiciones distintas no establecen un benchmark ni garantizan repetibilidad del contenido.

## Confinamiento operativo al cierre

La inspección final del listener encontró Ollama en `::11434`, aunque QuickPrompt solo lo llama por 127.0.0.1. Se detuvo el tray/servidor existente y se reinició el mismo ejecutable instalado con `OLLAMA_HOST=127.0.0.1:11434` y `OLLAMA_NO_CLOUD=true`, sin descargar modelos. Ambas variables se fijaron en ámbito **User** para próximos arranques; un proceso antiguo no recibe nuevas variables hasta reiniciarse. [Antes/después y comprobación](evidence/goal04/ollama-confinement.json). El reinicio de Windows/tray no fue probado.

Para reproducir el arranque de Ollama ya instalado, primero detener su instancia propia y en PowerShell ejecutar `$env:OLLAMA_HOST='127.0.0.1:11434'; $env:OLLAMA_NO_CLOUD='true'; ollama serve`. Verificar `Get-NetTCPConnection -State Listen -LocalPort 11434` y `/api/tags`. No ejecutar pull/install. No se modifican modelos ni preferencias de QuickPrompt. OLLAMA_HOST de usuario estaba ausente; para revertir ese ajuste explícito puede quitarse mediante `[Environment]::SetEnvironmentVariable('OLLAMA_HOST',$null,'User')`. Revertir desactivación de nube solo si el usuario decide cambiar su preferencia local; el valor previo de OLLAMA_NO_CLOUD de usuario no fue capturado, por lo que no se afirma rollback exacto de esa variable. Mantener ambos valores actuales respeta este alcance local.
